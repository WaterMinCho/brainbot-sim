# 01. 좌표계와 자세

## 자세 (pose)
평면 위 로봇의 상태는 숫자 셋이다.

| 값 | 뜻 | 단위 |
|---|---|---|
| x | 가로 위치 | m |
| y | 세로 위치 | m |
| θ (theta) | 로봇이 바라보는 방향 | rad |

위치(position)는 (x, y)만, 자세(pose)는 방향까지 포함한다. 로보틱스에서 두 말을 구분해 쓴다.

## 규약 (ROS REP-103)
- 단위는 m, rad, s
- 로봇 기준으로 x축이 앞, y축이 왼쪽
- 각도는 반시계 방향이 양수. θ = 0이면 +x 방향을 본다

실제 로봇 소프트웨어가 이 규약을 쓴다. 처음부터 맞춰 두면 M9에서 ROS2를 붙일 때 바꿀 것이 없다.

## 좌표계는 두 개다
| 좌표계 | 원점 | 쓰임 |
|---|---|---|
| 월드 (world) | 지도의 고정된 한 점 | 로봇과 벽의 위치 |
| 로봇 (body) | 로봇 중심. 로봇과 함께 움직인다 | 센서가 본 것 ("내 앞 1m에 벽") |

로봇 좌표계의 점 (bx, by)를 월드 좌표로 바꾸려면 θ만큼 돌리고 로봇 위치만큼 옮긴다.

```text
wx = x + bx·cos θ − by·sin θ
wy = y + bx·sin θ + by·cos θ
```

확인: 로봇이 (2, 1)에서 θ = 90°로 서 있다. 로봇 앞 1m, 즉 (bx, by) = (1, 0)은 월드에서 어디인가?
cos 90° = 0, sin 90° = 1이므로 wx = 2 + 0 − 0 = 2, wy = 1 + 1 + 0 = 2. 답은 (2, 2). 로봇이 위를 보고 있으니 앞은 위쪽이다.

CSS의 `transform: translate() rotate()`와 같은 계산이다. 다만 화면 좌표와 방향이 다르다.

## 화면 좌표는 y가 아래로 자란다
| | 월드 | 화면 |
|---|---|---|
| 단위 | m | 픽셀 |
| 원점 | 임의 | 왼쪽 위 |
| y가 커지면 | 위 | 아래 |
| 양의 회전 | 반시계 | 시계 (y가 뒤집혀서) |

변환식 (ppm은 1m당 픽셀 수, (ox, oy)는 월드 원점이 놓일 화면 위치):
```text
px = ox + x · ppm
py = oy − y · ppm
```
이 변환은 gui 계층 한 곳에만 둔다. core는 픽셀을 모른다. M2에서 구현한다.

## 각도 정규화
θ = 370°와 θ = 10°는 같은 방향이다. 그대로 두면 두 가지가 곤란하다.
- 값이 끝없이 커진다.
- 두 각도의 차이를 구할 때 틀린다. 350°와 10°의 차이는 340°가 아니라 20°다.

그래서 각도를 한 바퀴 범위 안으로 접는다. 이 프로젝트의 범위는 −π 이상 π 이하다.
경계(정확히 ±π)에서는 부동소수 오차 때문에 π와 −π 어느 쪽이 나와도 같은 방향이므로 둘 다 허용한다.

방법은 두 가지가 흔하다.
- 나머지 연산을 쓴다. 파이썬의 `%`는 자바스크립트와 달리 음수에서도 0 이상을 돌려준다.
- `atan2(sin θ, cos θ)`를 쓴다.

## atan2
`atan2(y, x)`는 원점에서 점 (x, y)를 바라보는 각도를 돌려준다. `atan(y / x)`와 달리 사분면을 구분하고 x = 0일 때도 동작한다. 인자 순서가 y 먼저다.

## 흔한 실수
| 실수 | 증상 |
|---|---|
| 도와 라디안을 섞는다 | 로봇이 빙글빙글 돈다. `math.sin`은 라디안을 받는다 |
| 화면의 y 뒤집기를 빼먹는다 | 왼쪽으로 돌라고 했는데 화면에서 오른쪽으로 돈다 |
| 각도를 정규화하지 않는다 | 한참 달린 뒤에 목표 방향으로 돌 때 먼 쪽으로 돈다 |
| `atan2(x, y)`로 쓴다 | 방향이 90° 어긋난다 |
