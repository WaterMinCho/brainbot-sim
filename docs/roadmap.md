# 로드맵

## 만들 것
사용자가 쓴 파이썬 "브레인" 코드로 2D 로봇을 움직이는 GUI 시뮬레이터.
처음 로봇은 두 바퀴 주행 로봇이고, M6에서 로봇팔을 더한다.

## 하지 않는 것
- 3D, 물리 엔진(질량, 마찰, 관성). 기구학만 다룬다
- 기존 시뮬레이터(Gazebo, Isaac Sim)의 대체. 이 프로젝트는 원리를 직접 구현해 보는 것이 목적이다
- M8 이전의 화려한 UI

## 설계 원칙
1. 코어가 먼저고 화면은 그 위에 올린다. 코어는 화면 없이 테스트로 검증한다.
2. 마일스톤 하나는 "돌려 볼 수 있는 결과물" 하나로 끝난다.
3. 부트캠프 진도와 맞물린다. 배운 것을 그 주에 시뮬레이터에 넣는다.
4. 실제 로봇의 규격을 따른다. 단위, 좌표계, 나중에는 ROS2 토픽 이름까지.

## 결정 기록
### 2026-09-27 첫 로봇은 두 바퀴 주행 로봇
- 이유: 상태가 (x, y, θ) 셋뿐이라 수학이 가장 단순하다. 결과가 바로 눈에 보인다. 센서, 판단, 구동의 전체 루프를 한 번에 경험한다.
- 부트캠프 실무 프로젝트는 협동로봇 중심이므로 로봇팔을 M6으로 앞당겼다.

### 2026-09-27 화면 라이브러리는 pygame-ce
- 이유: 루프를 직접 짜야 해서 시뮬레이션의 구조를 배운다. 설치가 쉽고 Windows와 Ubuntu에서 같게 동작한다.
- 코어와 화면을 분리해 두므로 M8에서 다른 도구로 바꿀 수 있다.
- 검토한 대안: PySide6(위젯이 풍부하지만 배울 양이 많다), 웹 화면(익숙한 기술이지만 파이썬 학습 목표와 어긋나 M11로 미뤘다).

### 2026-09-27 파이썬 3.10 이상 지원
- 이유: ROS 2 Humble이 3.10, Jazzy가 3.12를 쓴다. 개발 PC는 3.13이므로 CI에서 3.10과 3.13을 함께 돌린다.

### 2026-09-27 M9(ROS2 브리지)를 M6(로봇팔)보다 먼저 한다
- 이유: 부트캠프의 ROS 과정이 12월이다. 배우는 시기에 바로 적용한다. 로봇팔은 1월 실무 프로젝트 직전에 한다.
